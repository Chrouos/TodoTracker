# 報表專案分布與每日趨勢融合設計

## 目標

將目前分開的「專案時間分配」甜甜圈圖與「每日趨勢」折線圖，融合成同一組可互相對照的報表視圖，讓使用者同時回答：每天投入多少時間、時間分布在哪些專案、以及某個專案在哪些日期投入最多。

## 核准方案

採用 A＋B 融合版，垂直排列在同一個報表區塊：

1. 上方：堆疊面積圖
   - X 軸為日期。
   - Y 軸為每日總工時。
   - 每個專案以自己的顏色堆疊，面積高度代表該專案當日工時。
   - 最上方邊界代表每日總工時。
2. 下方：專案 × 日期 Heatmap
   - 列為專案，欄為日期。
   - 儲存格顏色深淺代表該專案當日工時。
   - 儲存格顯示簡短工時；完整資訊由 hover tooltip 提供。

## 互動

- Hover 任一日期：上方面積圖的日期線、下方 Heatmap 的日期欄同步 highlight，並顯示該日總工時與各專案工時。
- Hover 任一 Heatmap 儲存格：顯示日期、專案、工時與佔當日比例。
- 點擊專案列或圖例：聚焦該專案，上方只顯示該專案趨勢，下方保留該專案相關列並標示其比例。
- 點擊「全部」或空白處：清除專案聚焦，回到完整資料。
- 既有日期範圍控制（今天、本週、本月、全部、自訂區間）維持不變，兩張圖使用同一批範圍資料。
- 既有專案樹鑽取若仍保留，聚焦後的資料範圍先套用專案樹 focus，再套用圖表互動 focus。

## 資料與計算

- 使用既有 `inRange()` 與 `db.durationSec()` 計算時間紀錄。
- 每日專案工時：依 `startedAt` 日期與 `projectId` 分組。
- 專案沒有直接掛時間紀錄但有子專案時，沿用目前報表的 rollup 規則，子專案時間向上累加。
- Heatmap 色階以目前顯示範圍內的最大儲存格工時作為上限；沒有工時的儲存格維持空白色。
- 未分類時間以既有灰色專案色顯示，名稱為「未分類」。

## 版面與可讀性

- 兩張圖共享日期順序與顏色圖例，避免使用者在不同圖表間重新對照。
- 專案數量過多時，Heatmap 顯示主要專案，其他專案收進「其他」列；tooltip 仍可顯示完整拆分。
- 小於 30 分鐘的儲存格不強制顯示文字，避免 Heatmap 擁擠，但 hover 仍提供精確時間。
- SVG 必須保留 `role="img"` 與可讀的文字 tooltip；不可只依賴顏色傳達資訊。
- 保留目前收合報表區塊的行為。

## 實作邊界

- 修改 extension options 報表頁；popup 不加入這組大型圖表。
- 可以新增圖表純函式與測試，但不引入第三方圖表套件。
- 既有甜甜圈圖可移除或改為 Heatmap 的摘要圖例，但不再與每日趨勢各自佔一個主要報表區塊。
- 不改動時間紀錄資料格式、日期範圍語意、專案資料模型或報表 KPI。

## 驗收條件

- 本週資料能在同一個報表區塊看到每日總工時與專案顏色組成。
- 任一日期 hover 時，上下圖的日期定位一致，tooltip 數字加總等於該日總工時。
- 任一專案聚焦後，面積圖與 Heatmap 的工時總和一致。
- 專案沒有資料、只有未分類資料、只有一天資料、以及日期範圍沒有紀錄時，畫面都有合理的空狀態。
- 既有報表、CSV、專案樹鑽取、日期範圍切換與既有測試不回歸。
