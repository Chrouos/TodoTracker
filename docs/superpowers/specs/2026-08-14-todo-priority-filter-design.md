# Todo 優先級篩選設計

## 目標

在 Chrome extension 的 Todo 管理頁支援優先級，讓使用者可以快速找到緊急或高優先度任務；同時修正目前資訊量偏低的任務數量摘要。

## 範圍

- Task 新增 `priority` 欄位。
- 優先級固定為四級：`urgent`（緊急）、`high`（高）、`normal`（一般）、`low`（低）。
- Todo 編輯表單新增優先級選單，預設為一般。
- Todo 工具列新增優先級篩選器，與現有專案篩選器及完成狀態開關同時套用。
- Todo 清單顯示每筆任務的優先級標籤。
- 任務數量摘要依完成狀態顯示有用資訊：未顯示完成項目時顯示「共 N 個未完成」；顯示完成項目時顯示「N 個未完成／共 M 個」。
- popup 的 Todo 清單同步支援優先級篩選與優先級顯示。

## 相容性

- 舊任務沒有 `priority` 時，一律以 `normal` 解讀，不需資料 migration。
- 儲存任務時將缺少的優先級正規化為 `normal`。
- 不改變既有任務的 ID、狀態、父子關係、專案關係與排序。
- 優先級只影響篩選與呈現，不改變既有排序規則。

## 介面行為

### 優先級選項

所有 Todo 優先級選單使用相同順序與文字：

1. 全部（僅篩選器）
2. 緊急
3. 高
4. 一般
5. 低

### 篩選

專案篩選先決定專案範圍（包含子專案），優先級篩選再比對任務的有效優先級；完成狀態篩選維持現有行為。三者可組合使用。

### 摘要

- `showDone` 為 false：不顯示完成項目，摘要為 `共 N 個未完成`。
- `showDone` 為 true：顯示全部項目，摘要為 `N 個未完成／共 M 個`。

## 實作邊界

- 以 extension 的 local storage 資料模型為主要實作目標。
- web Todo 頁目前也使用同一份概念模型，但本次不擴大到 web UI；web 端保留對缺少 `priority` 的相容性，避免型別與資料讀取被破壞。
- 不新增複合排序、批次修改或優先級自訂功能。

## 測試與驗收

- 資料層測試確認新建任務預設 `normal`，舊任務讀取與更新會保留／補上有效優先級。
- Todo render/filter contract 測試確認表單、篩選器、篩選邏輯、優先級標籤與摘要文字存在。
- 既有 extension 測試全部通過。
- 手動驗收：建立四種優先級任務；切換優先級與專案篩選；切換顯示完成；重新載入 options 頁與 popup，確認篩選狀態與顯示正確。
