# 專案工作區設計

## 目標

讓使用者先選取一個專案，再從同一個專案工作區查看相關任務、工作週期、Todo 筆記、工作日誌、專案狀況、總工時與報表。

## 路由與入口

- 專案清單保留現有新增、編輯、封存與階層管理功能。
- 點擊專案名稱進入 `/projects/[projectId]`。
- 專案工作區可返回專案清單。
- 若專案不存在，顯示明確的找不到專案狀態。

## 資料範圍

- 目前專案與所有子專案視為同一個工作範圍。
- 相關 Todo：`task.projectId` 屬於工作範圍的任務。
- 相關工作日誌：`entry.projectId` 屬於工作範圍，或 `entry.taskId` 對應到工作範圍內 Todo。
- 所有統計均排除已刪除紀錄；工時只計算已結束的計時紀錄。
- 不改變既有 Todo、Entry、Project 的儲存格式與編輯流程。

## 工作區區塊

1. **概況**：專案名稱、階層路徑、目前狀況、總工時、Todo 總數、完成率、逾期數。
2. **工作週期**：依 Todo 的開啟時間、到期日、完成時間與最近工作日誌，整理目前工作週期；沒有專案專屬日期欄位時不自行新增虛構日期。
3. **Todo**：依 `todo`、`doing`、`done` 分組，顯示標題、到期日、Todo 筆記、累積工時與逾期狀態。
4. **工作日誌**：依日期倒序顯示計時紀錄，包含時間、Todo／描述、工時與工作筆記；同一筆紀錄只顯示一次。
5. **報表**：顯示每日工時、Todo 工時分布與狀態摘要，沿用既有時間格式與專案統計邏輯。
6. **專案筆記**：顯示並編輯目前專案的文字筆記；圖片與公開分享功能維持 feature flag 關閉。

## 元件與資料流

- 建立 `ProjectWorkspace` 頁面與共用的 `projectWorkspace` 聚合 helper。
- 聚合 helper 接收 `projectId`、projects、tasks、entries，回傳範圍內的專案、Todo、Entry、統計與工作週期資料。
- 專案詳細頁透過既有 `useStore()` 取得 snapshot，編輯仍使用既有 `act('upsertProject' | 'upsertTask' | 'upsertEntry')`。
- 不在專案工作區複製另一套儲存狀態；編輯後呼叫 store refresh，所有區塊使用同一份資料。

## 空狀態與錯誤處理

- 專案沒有 Todo、工作日誌或報表資料時，各區塊顯示獨立空狀態。
- 專案不存在時不渲染其他專案資料。
- 失去 extension bridge 連線時沿用既有 `Disconnected` 狀態。
- 子專案資料應納入統計，但在 Todo 與日誌列中標示來源專案，避免混淆。

## 驗證

- 測試聚合範圍、子專案納入、Entry 去重、刪除紀錄排除、總工時與完成率。
- 測試專案不存在、空專案與只有工作日誌的專案狀態。
- 執行 web TypeScript typecheck 與 production build；手動確認從專案清單進入、返回、編輯 Todo／筆記後工作區同步更新。
