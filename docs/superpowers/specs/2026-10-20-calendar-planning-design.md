# Extension 日曆規劃與實際計時設計

日期：2026-10-20

狀態：使用者已於 2026-10-20 核准，進入實作計畫階段；尚未開始實作。

## 使用目的與已確認方向

使用者希望在 extension 管理面板一眼看出每天、每段時間預計做什麼，以及實際做了什麼。參考圖包含月曆、時間區塊與清單。

已確認：安排可以獨立存在，例如開會、運動、休息；也能連到既有 Todo。同一個 Todo 可以安排多個時段。

本設計採用的具體預設：以週檢視為預設，提供月、週、日、清單四種檢視；計畫與實際並列；支援全天、跨日與拖曳調整。本次主要交付 extension 管理面板，web 保持資料契約相容。

## 現況

- `extension/src/options/options.html` 的報表已有每日工作回顧日曆，僅顯示實際 entries。
- Todo 的 `dueDate`／`dueTime` 表示截止時間，沒有預計開始與結束時間。
- `schedules` 表示到指定星期與時間自動建立 Todo，沒有安排時段資料。
- `db.js` 是 chrome.storage.local 的唯一存取層；popup、管理面板與 web RPC 共用 timer。
- web 的 `Snapshot` 經由 background `getAll` 取得；備份由 `exportAll`／`importAll` 處理。
- 專案刪除目前會刪除該專案的 Todo、保留實際紀錄並清除對應關聯，日曆須遵循同一資料生命週期。

## 方案選擇

1. **獨立安排資料，連結 Todo 與實際紀錄，採用本方案。** 支援沒有 Todo 的活動、一個 Todo 多個時段，以及一次安排多次計時。代價是增加一種資料集合與關聯管理。
2. 在 Todo 增加預計開始／結束欄位。資料較少，但獨立活動與多時段都需要額外包裝成 Todo，無法自然滿足已確認需求。
3. 只把現有截止日、週期排程與 entries 放進日曆。變動較小，但缺少真正的時段規劃能力。

## 畫面與導覽

新增獨立「日曆」分頁，放在「計時」之後。沿用既有字體、按鈕、專案顏色與設計 tokens。

工具列提供：今天、上一期／下一期、目前日期範圍、月／週／日／清單切換、新增安排。預設顯示本週，以設定中的 `weekStartsOn` 決定週起始日。

提供專案篩選與「計畫／實際／截止日」顯示開關。未分類是明確的篩選選項；各檢視共用選取日期與篩選狀態。第一版只在目前頁面保留這些狀態，不新增全域設定。

### 月檢視

- 固定七欄，依月份需要顯示四至六週，包含相鄰月份日期；今天有明確標記。
- 顯示安排、實際紀錄與截止日標記，以文字或圖示區分類別，不能只靠顏色。
- 跨日安排在每週內顯示連續橫條，跨週時拆成延續片段，仍對應同一筆資料。
- 每格最多顯示三筆，超過顯示「另 N 筆」；點擊後以所選日期進入日檢視查看全部。
- 每天顯示定時安排總時數與實際總時數，全天安排另顯示筆數。
- 點日期進入日檢視；點日期格的新增按鈕開啟全天安排表單。可將安排拖到另一日期，保留當地時間、跨日跨度與全天天數。

### 週／日檢視

- 以當地日期與 00:00–24:00 時間軸顯示，每天分成「計畫」「實際」兩欄，兩欄共用時間刻度。
- 計畫採專案色外框／淡底，實際採專案色實底；每塊都有類別、標題與起訖時間。未分類使用中性色。
- 全天安排與只有日期的截止日放在時間軸上方；有截止時間的 Todo 以時間標記顯示，不占用工作時段。
- 顯示目前時間線；初次進入時捲到目前時間前一小時，查看其他日期則捲到 08:00。完整 24 小時仍可捲動查看。
- 點空白時段新增預設 30 分鐘安排；框選時段指定長度，使用 15 分鐘格線。表單仍允許精確輸入到分鐘。
- 拖曳計畫改時間，拖曳上下邊緣改長度，最短 15 分鐘；跨日安排以表單調整起訖，畫面拆段後不提供拖曳與縮放，避免只改到片段。
- 重疊區塊以欄內分道呈現，允許計畫衝突，標示「時段重疊」。相鄰但不相交的區塊不算衝突。
- 實際紀錄不可直接拖曳；點擊開啟現有紀錄編輯流程。
- 窄畫面保留可水平捲動的週欄及固定時間刻度，提供清楚的日／清單切換。

### 清單檢視

- 顯示選取日期起七天的安排與實際紀錄，按日期、開始時間排序；全天安排排在當日最前面。
- 每筆標示計畫／實際／截止、專案與時間；每天顯示計畫及實際總時數。
- 上一期／下一期以七天移動；空日期顯示「沒有安排或紀錄」，仍可直接新增。

## 安排的建立與編輯

表單包含標題、專案、選填 Todo、全天開關、開始與結束、備註。標題必填；選 Todo 時可帶入標題及專案，使用者仍可修改標題。

- 選擇 Todo 後，專案與該 Todo 保持一致；改成不同專案時先解除 Todo 連結，表單明確顯示變更。
- 第一版可連結未封存的 Todo，包含已完成項目；已完成項目標示狀態。
- 修改 Todo 的標題或專案不會自動改寫已保存安排，安排保留自己的標題與專案快照。再次選取 Todo 才重新帶入。
- 備註沿用現有 Markdown 編輯器，不建立另一套編輯行為。
- 儲存、取消、刪除，以及「開始計時」是明確的按鈕。刪除安排需在編輯視窗內確認；顯示是否有關聯實際紀錄。
- 錯誤保留表單輸入並顯示原因；儲存成功後才關閉視窗。拖曳失敗則還原原位置並顯示錯誤。
- 點擊、鍵盤操作與表單可完成所有必要操作，拖曳是額外操作方式。

## 計畫與實際的對應

- 按安排的「開始計時」，使用既有單一 timer，帶入安排的標題、專案、Todo，以及新增的 `planId`。
- 安排備註保留為計畫說明，不自動複製到實際工作筆記。
- 已有其他計時時，依現有開始計時流程先儲存目前編輯與筆記、停止並保存原紀錄，再開始所選安排；不新增第二個並行 timer。
- 若已經在計時同一個安排，按鈕顯示「前往計時」，不停止重開。
- 停止計時後把 `planId` 保存到 entry；可在 popup、管理頁或 web 停止，關聯都必須保留。
- 修改目前計時的 Todo 或專案，若與來源安排的快照不一致，解除 `planId`；只改描述、筆記、標籤不解除。計時表單顯示目前來源安排，並提供解除連結。
- 沒有 `planId` 的歷史紀錄仍完整顯示，不以標題、時間或相同 Todo 猜測配對。第一版不提供歷史紀錄手動配對。
- 安排詳情顯示原計畫時間、關聯的實際紀錄及實際總時數；同一安排可對應多筆 entries。
- 開始／停止計時不改動原計畫起訖，不自動完成或刪除安排；Todo 完成仍沿用原本明確勾選的流程。

例：安排 09:00–11:00 寫功能，實際 09:30–10:30 與 11:00–12:00 做了兩次。計畫保留兩小時區塊，實際欄顯示兩段；安排詳情顯示兩筆關聯紀錄與合計兩小時。

## 資料契約

新增 storage key `calendarPlans`，由 `db.js` 提供 `listCalendarPlans`、`upsertCalendarPlan`、`deleteCalendarPlan`。資料形狀以判別聯集定義：

```ts
type CalendarPlanBase = {
  id: string;
  title: string;
  projectId: string | null;
  taskId: string | null;
  notes: string;
  createdAt: string;
  updatedAt: string;
};

type CalendarPlan = CalendarPlanBase & (
  | { allDay: false; startedAt: string; endedAt: string }
  | { allDay: true; startDate: string; endDate: string }
);
```

- 定時安排使用有效 ISO UTC 時間字串，顯示與輸入依裝置當地時區；`endedAt > startedAt`。
- 全天安排使用 `YYYY-MM-DD`，`endDate` 為不含結束日。例如 10/20 一天，儲存 10/20 至 10/21。全天不換算成 24 小時計入工時。
- 所有時間範圍採半開區間 `[start, end)`，午夜結束不會在隔天產生空白片段。
- 儲存時僅保留目前種類需要的時間欄位，切換全天時移除另一種時間欄位。表單開啟時保留暫存值，直到儲存才正規化。
- 既有 `Timer`、`Entry` 增加可選的 `planId?: string | null`。舊資料視為 null；更新舊紀錄時若未提供此欄，保留原值，明確 null 才解除。
- timer 的建立、修改、閒置處理、停止，以及紀錄編輯都須保留該欄。新 timer 未傳入時為 null，不能繼承上一個 timer。
- `calendarPlans` 為空時直接回傳空陣列，不需要資料搬移。
- 刪除 Todo 時保留安排並清除 `taskId`；刪除專案時保留安排，清除該專案及被刪 Todo 的關聯。標題、時間與備註保留。
- 刪除安排時保留所有實際紀錄，清除 entries 與目前 timer 的對應 `planId`；正在計時的時間與筆記不受影響。
- 專案封存不刪安排，已有安排仍顯示封存專案名稱及顏色；新增安排的專案選項遵循現有封存篩選。

## 日期、統計與更新

- 以實際當地日期邊界切分跨日資料；計算月、週與下一天時使用日曆運算，不能假設每天都是固定 24 小時。
- 定時安排與 entries 都以與可見區間的相交部分納入，避免只依開始日期篩選漏掉跨日資料。
- 每日計畫時數加總當日的各定時安排片段；重疊安排各自計入並標示衝突。實際時數同樣逐筆加總，與紀錄報表的計算方式對齊。
- 進行中 timer 顯示為「計時中」，每分鐘更新末端與當日暫計時數。以 `entryId` 排除可能重複的 entry，避免停止過渡期雙算。
- 已保存 entries 使用現有計時進位後的起訖，日曆不額外進位。
- 截止日只作標記，不計入安排時數；隱藏已完成、已封存 Todo 的截止標記，保留原安排及實際紀錄。
- 寫入成功與頁面重新取得焦點時重新讀取資料；監聽相關 storage 變更以反映 popup 操作。背景重新整理不得清空未儲存表單或中斷拖曳。

## 模組與資料流

- 新增 `extension/src/lib/calendar.js`：純日期運算、可見範圍、切段、分道、每日統計與輸入正規化。以純函式測試時間邊界。
- 新增 `extension/src/options/calendar.js` 與 `calendar.css`：日曆渲染、表單、互動、鍵盤與畫面狀態。由 options 提供 snapshot、資料操作及現有計時／紀錄導覽接口，避免讓既有大型 `options.js` 承擔全部細節。
- `options.html` 提供日曆分頁容器；`options.js` 負責初始化、載入資料與各分頁銜接。
- `db.js` 負責驗證及持久化、關聯清理與備份，不讓日曆 UI 直接存取 storage。
- `background.js` 的 `getAll` 回傳 `calendarPlans`，提供安排 CRUD RPC；允許的 origin 維持現有 localhost 規則。
- `web/lib/types.ts` 補上 CalendarPlan、Snapshot 與 timer／entry 欄位；檢查 web 的計時與編輯 payload 不會遺失關聯。第一版不新增 web 日曆頁面，也不在 web 複製未使用的日曆演算法。
- popup 若編輯 timer 或重啟最近紀錄，遵守前述關聯規則；從最近紀錄重新開始視為一般新計時，不繼承歷史 `planId`。
- 介面文字加入繁中、英文、日文翻譯，日期與時間格式沿用目前語系設定。

## 備份與相容性

- `exportAll` 在既有 version 1 備份加入 `calendarPlans`，維持既有格式的加法擴充。
- `importAll` 缺少 `calendarPlans` 時視為空陣列；可還原現有舊備份。
- 新格式備份匯入前驗證安排欄位、日期與起訖；任何安排無效則拒絕整次匯入，寫入前回報問題，避免部分覆蓋。
- 匯入時無效的 projectId、taskId、planId 清成 null，時間與文字仍保留；驗證及關聯正規化完成後才執行既有批次寫入。
- 舊版 extension 不認得新增欄位，不能保證用舊版匯入後仍保有安排；新版 README 說明備份還原應使用本功能版本或更新版本。
- 本次不新增雲端同步與 Supabase schema；資料仍保存在瀏覽器，沿用既有 web bridge。

## 第一版範圍外

外部 Google／Outlook 行事曆同步、邀請他人、獨立時區選擇、重複事件規則、安排提醒通知、自動排程、歷史紀錄手動配對，均不在第一版。

既有週期排程繼續負責自動建立 Todo；建立出的截止日可以顯示在日曆，但週期規則不自動推算成未來的計畫區塊。

## 驗證與驗收

1. 可建立不綁 Todo 的定時／全天安排，重新載入後仍存在；同一 Todo 可安排多天多段。
2. 月、週、日、清單切換與前後導覽正確，支援週起始日、跨月／跨年、閏日、午夜、跨日和當地夏令時間邊界。
3. 點擊、框選、拖曳與縮放能正確保存；取消或失敗不改原資料；鍵盤及表單可完成相同行為。
4. 重疊安排、相鄰時段、很短的實際紀錄、跨週橫條及大量資料的更多入口可正常呈現。
5. 計畫與實際可同時辨識；安排開始計時、popup 停止、分次計時及計時切換都保留正確關聯，不雙算。
6. 刪除安排、Todo、專案不連帶遺失實際紀錄；新增備份往返及舊備份還原符合上述規則。
7. 報表、管理計時、popup、現有週期排程與 web 編輯流程通過回歸測試。
8. 執行 `node --test extension/src/lib/*.test.js extension/test/*.test.mjs`、web 的 `npm run typecheck`、`npm run build` 及 `git diff --check`。
9. 用可重現測試資料進行瀏覽器驗證，檢查桌面與窄畫面、三種語言、實際拖曳和跨介面更新，提供日曆截圖供檢視。
